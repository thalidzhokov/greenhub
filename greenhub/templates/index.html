greenhub

Генератор коммитов для таймлайна (contribution graph) профиля GitHub.
Равномерно заполняет выбранный период или "рисует" текст пиксельным шрифтом.
Коммиты создаются задним числом в ваш репозиторий, превью показывает результат до пуша.
Позволяет настроить ачивки профиля GitHub.
Исходный код находится по ссылке github.com/thalidzhokov/greenhub.

Репозиторий

URL репозитория
Какой репозиторий указать?

Лучше создать отдельный новый репозиторий на своём аккаунте — сюда будут заливаться сгенерированные коммиты, напр., https://github.com/thalidzhokov/greenhub-repo.git. Создать репозиторий можно по ссылке github.com/new.

Чтобы коммиты попадали на таймлайн, репозиторий должен быть публичным или в профиле включён показ приватных контрибуций.

Токен
Как получить токен?

Нужен Personal Access Token (PAT) — токен создаётся в настройках вашего аккаунта GitHub. Есть два варианта:

  1. Fine-grained PAT (рекомендуется): github.com/settings/personal-access-tokens → Generate new token. Настройки:
    • Repository access -> Only select repositories -> выбрать репозиторий для коммитов указанный в URL репозитория;
    • Permissions -> Repository permissions -> Contents -> Access: Read and write

      Дополнительно для ачивок:

      • Issues -> Access: Read and write
      • Pull requests -> Access: Read and write
  2. Classic PAT: github.com/settings/tokens → Generate new token (classic) → scope repo. Минус - даёт доступ ко всем вашим репозиториям сразу.

      Ачивки профиля
      

        Как начисляются ачивки?
        

          GitHub пересчитывает ачивки с задержкой — бейджи появляются в профиле через несколько часов после прогона.
          YOLO выпадает само на первом мерже Pull Shark или Pair, отдельный прогон нужен, только если они не отмечены.
          Pull Shark считает смердженные PR, Pair Extraordinaire — co-authored коммиты в смердженных PR (прямые пуши в main не засчитываются).
        

        

          Коммиты для PR — обычные сниппет-коммиты таймлайна: каждый занимает свободный день плана,
          дни раздаются от свежих к прошлым (Pair первым, Pull Shark дальше в прошлое), по одному PR на день.
          Мерж идёт rebase'ом, так что клетки ложатся на запланированные даты.
          Кончились свободные дни — остаток тира добирается следующими прогонами.
          Само открытие issue и PR GitHub тоже считает контрибуциями, и эти события всегда
          датируются днём прогона — столбик за них в сегодняшней клетке не убрать.
        

      

      

        
        

          Что делает Quickdraw?
          

            Бейдж за issue или PR, закрытый в течение пяти минут после открытия.
            Сервис открывает в репозитории issue и закрывает его через минуту.
            Тиров нет, одного раза достаточно.
          

        

        
        

          Что делает YOLO?
          

            Бейдж за PR, смердженный без ревью. Тиров нет, одного раза достаточно.
            Если отмечены Pull Shark или Pair Extraordinaire, отдельный PR не создаётся —
            YOLO выпадает на первом же их мерже.
          

        

      

      

        
        
      

      

        Что делает Pull Shark?
        

          Бейдж за смердженные PR: 2 — базовый, 16 — бронза (x2), 128 — серебро (x3), 1024 — золото (x4).
          Сервис создаёт PR со сниппет-коммитом на свободный день плана и сразу мержит, повторяя до выбранного тира.
          Уже смердженные PR автора учитываются — прогон делает только недостающие, но не более 300 за раз
          и не больше, чем осталось свободных дней; остаток добирается повторным запуском.
        

      

      

        
        
      

      

        Что делает Pair Extraordinaire?
        

          Бейдж за коммиты с соавтором в смердженных PR: 1 — базовый, 10 — бронза (x2), 24 — серебро (x3), 48 — золото (x4).
          Сервис делает сниппет-коммит с трейлером Co-authored-by (один соавтор на коммит)
          на свободный день плана, открывает PR и мержит.
          Ачивку получают оба: и автор, и соавтор из трейлера — подтверждение от соавтора не требуется.
        

      

    


    

      

        Соавторы — по одному на коммит
        

          В каком порядке берутся соавторы?
          

            Первый co-authored коммит прогона с {{ owner_coauthor }}.
            Дальше знакомые из поля по списку, каждый по разу. Затем случайный выбор из отмеченных групп, перемешанных вместе.
            Повторы возможны, только когда выбраны одни сервисные аккаунты, со знаменитостями каждое имя используется не более одного раза.
          

          

            Соавторство засчитывается только с аккаунтами пользователей: организации и боты GitHub не привязывает к трейлеру.
            Перед прогоном каждый логин проверяется через API, неподходящие пропускаются с записью в лог.
          

        

        

          
          

            Почему {{ owner_coauthor }}?
            

              Это автор проекта greenhub. Первый co-authored коммит прогона уходит ему, ровно один за прогон, коммиты создаются его кодом, так что назвать это атрибуцией инструмента, а не спамом в чужой профиль; репорт за одну такую запись не прилетит.
              Автор коммита не может быть своим соавтором.
            

          

          
          

            Кого указывать?
            

              Лучше всего указать знакомых, которые сами хотят Pair Extraordinaire, ачивка начисляется обоим, подтверждение не требуется, а взаимный прогон закроет тир и им. Указывайте тех, кто в курсе, co-authored коммиты попадают в таймлайн и активность профиля соавтора.
            

            

              Незнакомцев вписывать не стоит - это записи в чужом профиле без спроса и повод для репорта.
              Каждый логин из поля используется один раз, в порядке списка.
            

          

          
          

            Какие сервисные аккаунты?
            

              Аккаунты ботов и сервисов, оформленные на GitHub как обычные пользователи, соавторство с ними засчитывается,
              а лишние коммиты в чужом личном профиле никому не мешают:
            

            
{{ bot_coauthors | join(", ") }}.

          

          
          

            Какие знаменитости?
            

              Известные разработчики; каждому уходит не более одного соавторства за прогон - одна co-authored запись
              теряется в их активности, но она попадёт в их профиль, поэтому группа выключена по умолчанию:
            

            
{{ celeb_coauthors | join(", ") }}.
